# DTC web-platform audit, 2026-11-11

The repo has no AGENTS.md and no existing research/ folder, so this file uses the fallback path.

## Verdict

Mixed. Data rendering is safe (React text nodes; no `innerHTML`; storage always in try/catch). Everything else the new rules cover is missing or partial. The main exposure is Electron hardening: the renderer renders agent-authored Markdown with no sandbox, no navigation guard and the whole `electronAPI` exposed. Then 20 hand-rolled ARIA modals, a light-only UI with an Appearance setting that does nothing, and unguarded smooth scrolls.

## Ranked fix list

1. Filter the external-link handler to `http:`/`https:` and render other `href`s as text (findings 3; S).
2. Remove `window.electron` from the preload so the renderer has only the typed `qa` bridge (2; S).
3. Turn on `sandbox: true` and state `contextIsolation`/`nodeIntegration` explicitly (1; S).
4. Add `will-navigate` block and a permission-request deny (4; S).
5. Tighten the CSP and settle the remote-image question (6, 7; S).
6. Route the six smooth scrolls through safe helpers (12; S).
7. Fix or make dark-theme honest: hide Dark/System until dark tokens exist, then build the System/Light/Dark switch with `color-scheme` (16; L, but hiding is S).
8. Add one `<Modal>` on native `<dialog>` and migrate the confirms first (10; L, staged).
9. Audit the `outline: none` rules and add a `forced-colors` block (13, 14; M).
10. Move menus to `popover`, and sender validation on IPC (11, 5; M each).

Rem font sizes (15) are left off the top ten: 621 edits for a benefit that depends on whether he wants OS text size to scale the UI.

Source reading and ripgrep over `src/renderer`, `src/preload`, `src/main/index.ts`, at commit efceddc; no app launch, no build, no tests. Line numbers are from that commit. The preload and IPC claims come from reading the code, not from a runtime probe.
